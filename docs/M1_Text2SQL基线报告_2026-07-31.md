## 一、评测口径（F1 落档摘要）

- **结果集等价**：值序列化后按行多重集合比对，允许行序差异；列按位置对齐；数值定点 6 位；NULL≠空串。
- **背靠背执行**：golden SQL 与生成 SQL 在同一评测运行中先后执行，禁止复用历史结果。
- **非确定性控制**：`temperature=0`，每题 3 次采样取多数票；指标附轮次波动区间。
- **空集题**：golden 返回空集的题目排除主指标（本题库 0 题）。
- **主指标**：生成率 / schema 校验通过率 / 首轮执行成功率 / 首轮结果正确率 / 端到端准确率（档 A 无重试，端到端=首轮）。

## 五、重要发现

**① schema 校验器误拦（已修复，`47e041d`）**：LLM 填写的 referenced_columns 混入 `SYSDATE`（伪列）、
`COUNT(*)`/`*`（表达式残留）、referenced_tables 混入包级过程（PKG.PROC），被校验器当真实表/列核对而误拦
合法 SQL。修复口径：非纯标识符跳过、伪列白名单跳过、带点条目不按基表校验。新增 3 个 JUnit 用例（10/10 绿）。
**该缺陷影响线上用户**，修复已随本次部署生效。

**② MESAPUSER 视图未授权（2026-08-01 已解决）**：只读账号逐表授权时漏了 154 个视图（`all_tables` 不含视图），
生成 SQL 引用 VW_* 视图时 all_tab_columns 查不到（误拦）且执行会 ORA-00942。
**处置结果**：TL 授权后补授完成——82 个视图直接授权成功；39 个因依赖 SCOAPUSER 底层对象
（SCO_CODE_DETAIL/SCO_CODE_MASTER + 12 个 FC_* 函数）报 ORA-01720，经「底层对象授 MESAPUSER
WITH GRANT OPTION」标准链修后全部授权成功；其余 33 个为克隆库固有 INVALID 死视图（不可用亦无需授权）。
验证：`VW_SQM_DSN_CHEM_CODE` 查询 V03→Mn 正确；`SCOAPUSER.VW_CODE_MASTER`（12,339 行）可直接查询。

**③ 铁律 6 副作用**：「时间过滤用 TO_CHAR(SYSDATE-n)」规则被模型泛化到**绝对时间窗**
（"2024年8月"→ 与 SYSDATE 常量比较，恒真/恒假）。M2 的 Prompt 修订须明确区分相对/绝对窗口。

**④ 2.4% 的解读**：正确率低的主因不是"生成不出来"（生成率 78%），而是**表/列/谓词选择的语义错误**——
正是 M2（schema linking + 执行反馈自纠错）的设计靶点。基线数字直接证实 M2 必要性。
