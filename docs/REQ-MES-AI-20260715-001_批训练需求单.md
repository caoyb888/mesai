## A. 背景与目标

**背景**：Sprint 3 将 AI 对真实 MES（韩系钢厂 MES，Oracle 21c XE / MESAPUSER 1860 表 / PL/SQL 193 万行）的 P0 核心资产形成可验证理解。S3-0 素材前置已全部本地完成、**未调用任何外部 AI**；S3-1/S3-2 的实际「理解训练」需将（脱敏后的）表卡片与子程序源码经标准 Prompt 送入 Kimi，属对外调用，依 CLAUDE.md §4.2 / §6 必须由已评审需求单授权。

- 全程脱敏零泄漏；Token 消耗在预算内；产出可 RAG 召回的理解卡片 + 子报告。

## C. 任务描述

对应 Sprint3 训练方案 S3-1 / S3-2，**按依赖拓扑序、分 P0 批次**执行：

**C-1（S3-1 表/字段批训练）**
1. 以 `prompts/sql/db-understanding.md`（AI-MES-PROMPT-SQL-001）为基座，注入表卡片 + 代码字典 + 术语表（RAG Top-5）。
2. 按模块分批（质量 BSQM / 调度 BSCH / 物料 / 设备 / 工单…）逐批送 Kimi 出理解结果。
3. 无注释表专项：仅凭命名 + %TYPE + 字典 + 过程用法推断，人工抽检纠偏。
4. 出《表/字段理解报告》+ 表理解卡片（入知识库，可 RAG 召回）。

**C-2（S3-2 存储过程批训练）**
1. 编写/复用存储过程理解 Prompt，注入**脱敏后**子程序源码 + 引用表卡片 + 术语表。
2. 拓扑序（先底层被调函数、后入口过程），逐子程序出【用途/业务规则/状态流转/读写副作用/调用依赖/风险与不确定点】。
3. 动态 SQL（13/60 含 `has_dynamic_sql`）专项：标注静态盲区，不臆断。
4. 近似重复包（BSQM_MTC_ISSUE_LZ/RZ/SHIP…按厂区复制）：训一迁移到变体，去重省 Token。
5. 出《存储过程理解报告》+ 过程逻辑卡片。
