## A. 背景与依据

- mes-sql 已上线真实执行（2026-07-30），首日实测暴露四类生成失败（臆造列 ×2、类型误用、码值缺失），

- 方案文档已定四层路径；本单覆盖第 1 层（评测基线）与第 2 层（执行反馈自纠错），
  第 3/4 层（语义层/微调）视本单效果另行立项。
- **没有基线数字，一切改进无法验收**——故评测基线与自纠错打包在同一单，先测后改、改完复测。

## B. 任务内容

### B1. 评测基线（先行）

1. **题库标注**：从 `L1L4_业务问答验收集_v0.1`（75 题）+ S3-1 SQL 验证题（30 题）中筛取适合取数的题目，
   每题标注 golden SQL（TL/BIZ 评审，抽样复核），落 `assertions/sql-logic/` 或专用题库 jsonl。
2. **评分脚本**（`scripts/verify/` 新增，纯 stdlib + 项目既有依赖）：
   批量调用 `/mes-sql/query` → 生成 SQL 与 golden SQL 分别在只读库执行 → **结果集等价**判对；
   输出指标：端到端准确率、生成率、schema 校验通过率、首轮执行成功率。
3. **基线报告**：当前系统（Prompt v1.2 + 双保险）跑一遍，数字落 `docs/`。

### B2. 执行反馈自纠错循环

1. **失败回喂重试**（核心）：
   - Java `MesSqlService`：schema 校验失败 / 执行 ORA 错误时，组装「错误信息 + 涉及表的 all_tab_columns
     真实列清单（含类型）」回调网关重新生成，最多 3 轮；每轮仍过安全校验 + schema 校验（防线不降级）；
   - 网关 `mes_sql.py`：支持重试请求（messages 追加历史轮次：上轮 SQL + 失败原因 + 真实列清单）。
2. **Schema Linking 前置**（生成侧提质）：
   - 生成前从问题确定性抽取候选表/列（代码字典直查 + `data_dictionary_full.csv` + 向量检索双路）；
   - Prompt 上下文改为「相关表的最小列子集（列名+真实类型+码值）」，替代整表卡片。
3. **预算保护**：仅失败请求进入重试（首轮成功不加价）；重试轮次硬上限 3；复用既有预算闸熔断。
4. **可选增强（视工期）**：重试仍失败时采样 3 候选试执行择优（self-consistency）。

### B3. 测试与复测

- 网关 pytest：重试收敛 / 重试耗尽 / 消息轮次拼装用例；Java JUnit：重试循环、终止条件、熔断用例。
- **复测验收**：B1 基线同一题库复跑，对比报告入 `docs/`。

## D. 预算与 §12 说明

- 重试仅对失败请求触发，预估平均 token 放大 ≤1.5×（按首日失败率估）；轮次硬上限 3。
- 评测基线批量跑题：105 题 × ~1.5K token ≈ **16 万 token/轮**，基线+复测两轮 < 50 万，默认日闸内。
- 无需临时预算闸。

## E. 执行方案（评审通过后）

```

```

## F. 验收标准

- 评测基线可重复执行，指标定义清晰（结果集等价）。
- 重试循环：当日四类实测失败案例（SPEC_CD / TRUNC / PROD_JDG_DTM / 中文标签）全部在无人工干预下自纠错通过。
- 同一题库复测：端到端准确率较基线提升 ≥15 个百分点；首轮成功率不下降。
- 安全防线不降级：每轮重试仍过 SqlSafetyValidator + SqlSchemaValidator；全程脱敏门；零硬编码。
- 网关 pytest / Java mvn test 全绿，新增用例覆盖重试路径。
