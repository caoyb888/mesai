## 一、目标与前置

**目标**：让 AI 对真实 MES 的 **P0 核心资产**（表/字段 + 存储过程 + 业务流程）形成可验证的准确理解，
输出《真实 MES 系统理解总报告》，为独立开发（Phase 2）打底。

**准确率目标**：表/字段 SQL 场景 ≥85%；存储过程理解 ≥85%；业务流程（状态机/追溯）≥90%；三语术语识别 ≥90%。

**前置（S2.9 已就绪）**：
- 全库结构自省 JSON（`meta_mes_nosrc.json`：1860 表/75965 字段/9160 单元）
- 字典对账清单（59,199 列「字典可反哺」= 列语义唯一来源）
- 依赖图谱工具 + 按 P0 名单拉源码（`db_introspect --source-units-file`）
- PL/SQL 静态分析（读写表/调用链/状态流转/PII/动态 SQL 标记）

## 二、五个必须正视的现实约束（决定方法论）

| 约束（来自实测） | 训练方法应对 |
|------------------|-------------|
| **活库列注释全空** | 语义靠「拼图」：字典注释 + 命名规约 + `SCO_DATA_DIC` 代码解码 + PL/SQL 用法 + 源码内中文行注释 |
| **中/韩/英三语**（韩系系统） | 先建**中韩英术语对照表**，训练/RAG 内容统一归一为中文，保留原文 |
| **193 万行、以包为主**（4563 包） | **不可全量**；按依赖图谱选 P0；大包**按子程序切分**再理解（单包体最大 1.6 万行，超上下文） |
| **大量动态 SQL** | `EXECUTE IMMEDIATE` 单元静态盲区，标记后由人工/运行期补表依赖，训练时明确标注不确定性 |
| **Token 预算 300 万/日** | P0 分批；表卡片/子程序摘要控长；250 万降级 Top-5→Top-3；发 Kimi 前强制脱敏 |

## 四、训练方法要点

**① 语义拼图（应对零注释）**：单一来源都不够，每个字段/表按优先级合成——
字典注释 > SCO_DATA_DIC 代码解码 > 命名规约 > PL/SQL 用法 > 源码行注释；冲突留痕交人工。

**② 三语归一**：韩文/英文术语经对照表归一为中文再训练，原文保留为参考；术语表本身纳入 RAG。

**③ 大包按子程序切分**：包体 → 各 PROCEDURE/FUNCTION 段独立理解 → 再合成包级摘要；避免超上下文、控 Token。

**④ 拓扑序训练**：先底层被调函数、后入口过程，让上层理解可复用下层结论。

**⑤ 标准 Prompt 结构**（CLAUDE.md 6.1）：系统角色 + RAG 上下文(Top-5) + 任务 + 约束 + 输出格式；
所有对外调用**先脱敏**。

**⑥ Token 预算**：P0≈100 表 + ≈40 包（约数百子程序）分批；单卡片/子程序摘要控长；
逼近 250 万降 Top-5→Top-3、压缩输出；逼近 300 万暂停非紧急。

真实库上已完成 S3-0 的关键前置（工具产物在 `scratchpad/graph_mes3/` 与代码字典 CSV）：

- **T3-0-1 全量依赖图谱**：`build_dep_graph.py`（内存安全批处理）跑通 MESAPUSER 全 9160 单元（约 7 分钟）→
  **过程 5101 / 表 2249 / 调用环 77 / 未解析外部调用 290**。Top 核心包体（BSCT_COST 成本、
  BSQM_MTC_ISSUE 质保书签发、BSCH_PROD_INST 生产指示、BSMS_OPER_BOF 转炉、BSPR_HEAT_FCE 加热炉）精准浮现。
- **T3-0-2 P0 选取**：**分级百分位在万级图上会把 P0 撑到 2117 个**（2046 入口 + 兜底规则），不适合直接训练；
  改用**按中心度评分取 Top-N** 作 Phase-1 实用集：`p0_phase1_tables.txt`（Top100 表）+
  `p0_phase1_units.txt`（Top60 包体）。规模按首周 Token 消耗再校准。
- **T3-0-5/6 代码字典/术语**：`SCO_CODE_DETAIL`（13620 行）= 代码解码表且**自带中韩双语**
  （`CD_NM` 中文 / `CD_DESC` 韩文，1297 组）→ 直接充当解码字典 + 中韩术语表；
  `SCO_CODE_MASTER`（组定义）、`SCO_DATA_DIC`（22687 行字段字典）一并导出。

**proc_parser 经真实库硬化 3 处**（类型名/子程序定义头/外连接 `(+)` 均曾被误当调用，已修复+单测）。

**闭环就绪**：`p0_phase1_units.txt` → `db_introspect --source-units-file` 拉 P0 包体源码 → `proc_parser` 深析 → S3-2 训练。

**T3-0-4 大包子程序切分（已实现并跑通）**：新增 `plsql_splitter.py`（长度保留掩码 + 命名 END 配对，
自测 + 13 pytest 通过）。对 60 P0 包切出 **1401 个子程序单元**（每个子程序 + 包级 PREAMBLE = 一个训练单元）：
- 校验：`BSMS_OPER_RFN` 切出 13 子程序，与人工计数一致；`BSCH_BATCHA_PLT_JOB2`（15929 行）→ 44 子程序，最大 1643 行（已可入上下文）。
- 86% 按「命名 END 子程序名;」精确闭合；**14% 裸 END 回退**（已 `fallback` 标记，失败模式是段偏大而非丢代码，安全）。
- 切分后仍有 9 个子程序 >2000 行（多为 fallback 段），标记待人工复核或二次切分。

**Top60 P0 包体深析（221,156 行）· 训练素材质量结论**：
- 结构清晰：子程序边界明确、`%TYPE` 列锚定（变量→列字典的天然语义桥，训练可重点利用）。
- 14 个大包（>5000 行，最大 BSCH_BATCHA_PLT_JOB2 15928 行）**必须子程序级切分**（证实 T3-0-4）。
- **注释语言混合（中/英/韩，按模块/作者不同）→ 注释不可靠**，**语义拼图**（命名+%TYPE+字典+SCO_CODE_DETAIL 解码）是必需而非可选。
- 13/60 含动态 SQL，训练标注盲区。
- **脱敏范围小于预期**：P0 源码 0 个真实硬编码（无 IP/连接串/邮箱），117 个"PII 候选"全是时间/哨兵常量（`235959` 等）误报 → **P0 源码脱敏基本不必要，PII 风险仅在数据样本**（T3-0-8 可聚焦数据样本；`proc_parser` long_number 启发式待优化）。
- **近似重复包**：BSQM_MTC_ISSUE_LZ/RZ/SHIP/SHIP_YC/SHIP_YC1 等按厂区/产线复制、画像一致 → 训练一个迁移到变体，去重省 Token。
