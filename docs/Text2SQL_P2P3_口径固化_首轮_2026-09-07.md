## 一、靶点：22 题"选对表却算错数"的根因

P1 后选对表 85%、结果正确 32%，差距是 22 题"选对表却算错数"。逐题回放归因：

| 根因 | 数量 | 典型 |
|------|------|------|
| **臆造过滤条件（P2）** | ~4 | Q11 加 `MTRL_SHP_TY='D'`、Q18 加 `FCE_CH_DISCH_FL=1`、Q19 加 `MSG_FLAG=1` |
| **多余列/总计列/汇总行（P3）** | ~7 | Q21/Q24/Q31 加 `SUM(COUNT(*)) OVER()` 总计列；Q20 多首列；Q23 加 GROUPING 总计行 |
| **计数/单位口径（P3）** | ~4 | Q01 用 `COUNT(DISTINCT)` 而非 `COUNT(*)`；Q15 擅自 `/1000` 换吨 |
| **日期列口径（P3）** | ~8 | Q01 用 `DE_C_TAP_END_DTM` 而非 `CRT_TM`；Q15/16/22 用 `FIN_END_DTM` 而非 `FIN_SUMUP_DT` |
| **码值接地（P2）** | ~2 | Q29 `CHEM_JUDG='9'`/`LIKE '%不合格%'` 而非 `'F'` |

## 二、改动：系统 Prompt 增补铁律 10~13

在原 9 条铁律后增补（均为口径约束，不改检索/执行）：

- **10（禁臆造过滤）**：不得加入问题未要求的状态/标志/归档/有效性等过滤（`*_FL`/`*_STS`/`*_YN`/`ARCHIVE_*`）；宁可少加，不臆造。
- **11（禁多余列/汇总）**：只返回问题所问的列；聚合/分布类只返回「分组列 + 计数/度量」；禁 `SUM(COUNT(*)) OVER()` 总计列、GROUPING 汇总行、无关附加列。
- **12（计数/单位口径）**：计数默认 `COUNT(*)`，仅问"不同/去重"才 `DISTINCT`；度量按库中原单位原精度，不擅自换算/四舍五入。
- **13（时间列口径）**：多日期列时优先"汇总/完成/创建"类（完工→`*_SUMUP`/`*_FIN`、记录产生→`CRT_TM`），避免误用计划/明细时点列。

## 四、残留失败（下一步）

P2/P3 铁律解决了臆造过滤、多余总计列、计数/单位口径大部；残留归三类：

1. **列语义映射（P3，需 schema_linking / 列注释 / 口径表）**：Q32/Q34"牌号"→ 模型用 `SPEC_CD`，golden 用 `STD_STLGRD`。
2. **码值接地（P2，需值索引）**：Q29 不合格→`F` 未命中（`_inject_code_dict` 未覆盖 `CHEM_JUDG`）。建议离线建"码值+中文标签"值索引并注入。
3. **golden/题面可议（评测复核）**：Q30"已完成"golden 返回全分布而非过滤计数；Q28 为何两列计数——交业务复核（承 `docs/评测口径修订说明`）。
4. **聚合类 0/6**：多为列语义 + 多余列残留，随 1、2 项解决。

**建议下一步顺序**：① 开启 schema_linking（让模型看到真实列+类型，缓解日期列/牌号列口径）→ 需 F5 档位复测；
② 离线值索引 + 注入（攻码值接地）；③ golden 复核（Q28/Q30 等）。
