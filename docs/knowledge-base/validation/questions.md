## 模块 01：基础数据管理

> 执行时将 `{product_code}` 等占位符替换为测试库中的真实值

### Q01-1（难度：⭐）
**场景**：查询某个产品的基本信息，包括产品编码、产品名称、规格型号和当前状态。

**评估要点**：
- [ ] 查询 product（产品主表）
- [ ] 明确列出字段，无 SELECT *
- [ ] 有参数化条件

**参考表**：`product`（产品主表）

---

### Q01-2（难度：⭐⭐）
**场景**：查询产品 `{product_code}` 的最新版 BOM 中的所有物料，显示物料编码、物料名称、用量和单位。

**评估要点**：
- [ ] JOIN product + bom_header + bom_detail + material（至少 3 表）
- [ ] 有版本过滤条件（只取生效版本）
- [ ] 用量和单位字段正确

**参考表**：`product`、`bom_header`（BOM 主表）、`bom_detail`（BOM 明细）、`material`（物料主表）

---

### Q01-3（难度：⭐⭐）
**场景**：查询工位 `{workstation_code}` 所在产线的所有工位列表，按工位序号排序。

**评估要点**：
- [ ] 正确关联 workstation + production_line
- [ ] 排序字段正确

---

### Q01-4（难度：⭐⭐⭐）
**场景**：统计各产品类别下的 BOM 数量（统计生效中的 BOM），按数量降序排列。

**评估要点**：
- [ ] 正确 GROUP BY
- [ ] 过滤 BOM 状态为"生效中"
- [ ] 有 ORDER BY

---

### Q01-5（难度：⭐⭐⭐）
**场景**：查询所有存在"原材料库存为 0 但 BOM 中用量 > 0"的物料，即潜在缺料风险物料。

**评估要点**：
- [ ] 关联 material + bom_detail + inventory（库存）
- [ ] 正确处理库存为 0 的过滤逻辑（含 NULL 处理）
- [ ] 业务逻辑准确（只取生效 BOM 中的物料）

## 模块 02：工艺管理

### Q02-1（难度：⭐）
**场景**：查询产品 `{product_code}` 的工艺路线，显示工序序号、工序名称、所在工位和标准工时（秒/件）。

**评估要点**：
- [ ] JOIN process_route + operation + workstation
- [ ] 按工序序号（seq）排序
- [ ] 标准工时单位正确

---

### Q02-2（难度：⭐⭐）
**场景**：查询某工位 `{workstation_code}` 上当前处于"生效"状态的所有工序，并显示所属工艺路线名称。

**评估要点**：
- [ ] 正确过滤工序状态
- [ ] JOIN 到工艺路线

---

### Q02-3（难度：⭐⭐）
**场景**：统计各产品的工艺路线工序数量，显示产品编码、产品名称和工序数，只统计有效工艺路线。

**评估要点**：
- [ ] GROUP BY 正确
- [ ] 过滤无效工艺路线

---

### Q02-4（难度：⭐⭐⭐）
**场景**：查询标准工时 > 某阈值（如 300 秒/件）的所有工序，显示产品、工艺路线、工序名称和标准工时，按标准工时降序。

**评估要点**：
- [ ] 参数化阈值
- [ ] JOIN 路径完整

---

### Q02-5（难度：⭐⭐⭐）
**场景**：找出所有"同一产品存在多个生效工艺路线"的异常情况（同一时间只应有一个生效版本）。

**评估要点**：
- [ ] 使用 GROUP BY + HAVING COUNT > 1
- [ ] 业务逻辑理解准确（同一产品同一时间只有一个生效版本）
- [ ] 附说明：为何这是异常数据

## 模块 03：生产计划管理

### Q03-1（难度：⭐）
**场景**：查询今日需要开工的生产工单列表，显示工单号、产品名称、计划数量和计划开始时间。

**评估要点**：
- [ ] 使用 CURRENT_DATE 函数
- [ ] 工单状态过滤（如已下达状态）
- [ ] JOIN product

---

### Q03-2（难度：⭐⭐）
**场景**：查询某工单 `{work_order_no}` 的当前执行进度，显示：计划数量、已完成数量、完成率（百分比，保留 1 位小数）。

**评估要点**：
- [ ] 完成率计算：`ROUND(finished_qty * 100.0 / plan_qty, 1)`
- [ ] 处理分母为 0 的情况（`NULLIF` 或 CASE WHEN）
- [ ] 参数化工单号

---

### Q03-3（难度：⭐⭐）
**场景**：查询本周内计划完工但尚未完成的工单，按计划完工时间升序排列（最紧急的排在前面）。

**评估要点**：
- [ ] 正确的日期范围（本周一到本周日）
- [ ] 工单状态过滤（未完成）

---

### Q03-4（难度：⭐⭐⭐）
**场景**：统计各产线本月每日的工单下达数量和计划总产量，生成"产线-日期"的生产计划密度热力图数据。

**评估要点**：
- [ ] DATE_TRUNC('day', ...) 按日聚合
- [ ] 关联 work_order + production_line
- [ ] 只统计本月数据

---

### Q03-5（难度：⭐⭐⭐）
**场景**：找出"计划数量与实际完成数量差异超过 20%"的工单，显示工单号、差异率，并标注是"超产"还是"欠产"。

**评估要点**：
- [ ] 差异率计算正确
- [ ] CASE WHEN 区分超产/欠产
- [ ] 只查已关闭（完成）的工单

## 模块 04：作业管理

### Q04-1（难度：⭐）
**场景**：查询工位 `{workstation_code}` 今日的所有报工记录，显示报工时间、操作员、报工数量和工单号。

**评估要点**：
- [ ] 日期过滤用 CURRENT_DATE
- [ ] JOIN 操作员信息

---

### Q04-2（难度：⭐⭐）
**场景**：查询当前所有在制品（WIP）的位置分布，显示各工序/工位的在制品数量，按数量降序。

**评估要点**：
- [ ] 查询 wip（在制品）表
- [ ] GROUP BY 工位/工序
- [ ] 过滤已完工（只看进行中）

---

### Q04-3（难度：⭐⭐）
**场景**：查询某生产批次 `[LOT_NO_***]` 的完整生产轨迹（在哪些工序停留过，每个工序的进入时间和离开时间）。

**评估要点**：
- [ ] **注意**：批次号使用脱敏格式 `[LOT_NO_***]`，SQL 中参数化
- [ ] 按时间顺序排列
- [ ] 涵盖所有工序节点

---

### Q04-4（难度：⭐⭐⭐）
**场景**：统计本月各操作员的日均报工量，找出报工量最低的 5 名员工（可能是问题员工或请假较多）。

**评估要点**：
- [ ] **注意**：员工工号脱敏为 `[EMP_ID_***]`，在展示层脱敏
- [ ] 日均计算：总报工量 / 有效工作日数
- [ ] TOP-N 查询

---

### Q04-5（难度：⭐⭐⭐）
**场景**：查询今日发生异常的工单列表，显示工单号、异常类型、异常工位、上报时间和当前处理状态，按异常严重程度降序排列。

**评估要点**：
- [ ] JOIN work_order + exception_record
- [ ] 严重程度排序（需理解枚举值含义）

## 模块 05：设备管理

### Q05-1（难度：⭐）
**场景**：查询工位 `{workstation_code}` 的所有设备台账，显示设备编码、设备名称、型号、当前状态。

**评估要点**：
- [ ] **注意**：设备序列号字段脱敏为 `[DEVICE_SN_***]`，不在 SELECT 中输出原始值
- [ ] 工位关联正确

---

### Q05-2（难度：⭐⭐）
**场景**：查询所有"超过 30 天未执行点检"的设备，显示设备名称、所在工位、最后一次点检时间和超期天数。

**评估要点**：
- [ ] 用 CURRENT_DATE - last_inspect_date 计算超期天数
- [ ] 处理从未点检（NULL）的情况
- [ ] 过滤停用/报废设备（无需点检）

---

### Q05-3（难度：⭐⭐）
**场景**：统计本季度各设备的故障次数和平均故障修复时长（MTTR），按故障次数降序排列。

**评估要点**：
- [ ] 本季度日期范围计算
- [ ] MTTR = 总维修时长 / 故障次数
- [ ] 关联 equipment + maintenance_order

---

### Q05-4（难度：⭐⭐⭐）
**场景**：找出"计划点检日期已到但仍未执行点检"的设备，按超期天数降序排列，生成点检催办清单。

**评估要点**：
- [ ] 区分计划点检日期与实际点检日期
- [ ] 处理周期性点检（需关联点检计划表）

---

### Q05-5（难度：⭐⭐⭐）
**场景**：查询设备可用率（OEE 中的可用率部分）：某时间段内，各设备的"运行时长 / 计划运行时长"，
以百分比显示，只取可用率低于 80% 的设备，按可用率升序。

**评估要点**：
- [ ] 理解设备状态字段的枚举值
- [ ] 时长计算（日期差转小时）
- [ ] 过滤条件正确

## 模块 06：质量管理

### Q06-1（难度：⭐）
**场景**：查询今日所有检验记录，显示工单号、产品名称、检验类型（全检/抽检）、检验结果和检验员。

**评估要点**：
- [ ] 日期过滤
- [ ] JOIN inspection_record + work_order + product + inspector

---

### Q06-2（难度：⭐⭐）
**场景**：统计本月各产品的不良品率（不良品数 / 检验总数 × 100%），保留 2 位小数，按不良品率降序排列前 10。

**评估要点**：
- [ ] 处理分母为 0 的边界情况
- [ ] TOP-N 查询
- [ ] 不良品率计算公式正确

---

### Q06-3（难度：⭐⭐）
**场景**：查询某产品 `{product_code}` 最近 3 个月的不良品类型分布，显示不良类型、数量和占比，按数量降序。

**评估要点**：
- [ ] 日期范围：最近 3 个月（非固定月份）
- [ ] 占比计算：SUM(qty) OVER () 窗口函数或子查询
- [ ] 关联不良类型字典

---

### Q06-4（难度：⭐⭐⭐）
**场景**：找出所有状态为"已隔离"但超过 7 天未处理的不良品，显示不良品批次、数量、隔离时间和超期天数，生成催办清单。

**评估要点**：
- [ ] 不良品状态枚举值理解（"已隔离"的具体值）
- [ ] 超期计算
- [ ] **注意**：批次号脱敏为 `[LOT_NO_***]`

---

### Q06-5（难度：⭐⭐⭐）
**场景**：计算本月"逃逸率"——已通过成品检验发货但后续被客户反馈有问题的批次比例，
按产品类别分组显示。（逃逸率 = 客诉批次数 / 发货批次数 × 100%）

**评估要点**：
- [ ] 需 JOIN inspection_record + shipment + customer_complaint 三表
- [ ] 逃逸率业务逻辑理解准确
- [ ] 附说明：此查询若无客诉表可先用占位逻辑展示

## 综合场景题（T2-1-5 实战验证）

### QZ-1（难度：⭐⭐⭐⭐ 跨模块）
**场景**：
"查询今日所有已下达的工单，显示：工单号、产品名称、计划数量、当前在制品数量（在哪个工序）、
对应工序的设备状态（正常/停机）、该产品本月的平均不良品率。"

**评估要点**：
- [ ] 跨越 4 个模块：生产计划 + 作业管理 + 设备管理 + 质量管理
- [ ] 正确识别各模块的 JOIN 键
- [ ] 考生能说明若某模块数据缺失时如何处理（LEFT JOIN vs INNER JOIN 的选择）
- [ ] 附执行计划分析

---

### QZ-2（难度：⭐⭐⭐⭐ 异常检测）
**场景**：
"设计一个'今日生产异常汇总'查询，整合以下信息：
1. 超期未点检的设备（设备管理）
2. 有未处理异常记录的工单（作业管理）
3. 不良品率超过 5% 的工序（质量管理）
4. 进度落后超过 20% 的工单（生产计划）
以 UNION ALL 形式汇总，标注异常类型。"

**评估要点**：
- [ ] 各子查询 SELECT 列数和类型一致（UNION ALL 兼容）
- [ ] 每个子查询逻辑独立正确
- [ ] 最终结果按异常严重程度排序
