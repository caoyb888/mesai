## 一、标准 Prompt 五段式结构

所有任务类 Prompt 必须包含以下五个段落，缺少任何一段视为不合规模板：

```
╔══════════════════════════════════════════╗
║  [系统角色定义]   §1 角色声明与能力边界    ║
║  [上下文注入]     §2 知识库 / 文档片段    ║
║  [任务描述]       §3 具体任务内容         ║
║  [约束条件]       §4 安全红线与质量要求    ║
║  [输出格式要求]   §5 交付物结构规范       ║
╚══════════════════════════════════════════╝
```

## 二、各段落内容规范

### §1 系统角色定义（System Role Definition）

**目的**：声明 AI 的身份、职责边界和技术背景，确保 AI 以正确的视角处理任务。

**必须包含**：
- 项目/岗位名称（芯智云匠 MES AI 开发工程师）
- 当前任务类型（开发 / SQL / 巡检 / 代码审查等）
- 技术栈版本（Java 11 / Spring Boot 2.7 / MyBatis Plus / Vue 2-3 / MySQL 8）
- 接口规范摘要（ResultVO 封装 / RESTful / JWT 鉴权）

**模板**：
```
[系统角色定义]
你是芯智云匠项目的 MES AI 开发工程师，服务于山东芯通微电子，
熟悉本系统的数据库结构、业务逻辑和编码规范。
技术栈：Java 11 + Spring Boot 2.7 + MyBatis Plus 3.5.5 + Vue 2/3 + MySQL 8.x
接口规范：RESTful API，统一 ResultVO<T> 封装（code=0 表示成功），JWT Bearer Token 鉴权
当前任务类型：{TASK_TYPE}
```

---

### §2 上下文注入（Context Injection / RAG）

**目的**：将知识库中检索到的相关文档片段注入 Prompt，提供任务所需的领域知识。

**检索策略优先级**：
1. 业务流程文档（确认业务规则）
2. 数据库数据字典（确认表结构和字段含义）
3. 接口文档（确认现有接口规范）
4. 历史问题记录（避免重复踩坑）
5. 行业最佳实践（CIM/MES 标准规范）

**格式规范**：
```
[上下文注入]
以下是从知识库检索到的相关文档（Top-{N}，按相关度排序）：

--- 文档片段 1 / {N} ---
来源：{知识库集合名称} | 类型：{db_structure / api_doc / business_flow}
{文档内容}
--- END ---

--- 文档片段 2 / {N} ---
...
--- END ---
```

**Top-N 推荐值**：

| 任务类型 | Top-N | 说明 |
|---------|-------|------|
| 单表/单模块开发 | 5 | 标准检索量 |
| 跨模块开发 | 8-10 | 需要更多上下文 |
| Token 超预算（>250万）降级 | 3 | 自动降级规则 |

---

### §3 任务描述（Task Description）

**目的**：清晰描述本次任务的具体内容，对应需求单的业务描述部分。

**必须包含**：
- 需求单编号（`REQ-MES-AI-YYYYMMDD-XXX`）
- 任务标题（与需求单标题一致）
- 具体功能/改动描述（用户故事或技术描述）
- 输入数据/依赖条件

**格式规范**：
```
[任务描述]
需求单：{REQ_NO}
任务：{TASK_TITLE}

{具体任务描述，包含：
  - 要实现的功能点（逐条列出）
  - 入参/出参要求
  - 业务规则（状态流转、权限控制等）
  - 关联的数据库表或接口}
```

---

### §4 约束条件（Constraints）

**目的**：声明安全红线、代码规范和质量要求，防止 AI 越界操作。

**强制约束（任何任务均须包含）**：

```
[约束条件]
代码规范：
- 注释语言：中文（所有 JavaDoc、方法注释、行注释）
- 命名规范：类名 UpperCamelCase，方法名 lowerCamelCase，常量 UPPER_SNAKE_CASE
- 接口返回：统一使用 ResultVO<T> 封装，禁止返回裸对象或 Map
- 日志规范：使用 @Slf4j，业务节点 INFO，异常 ERROR（含完整堆栈）

安全红线（零容忍）：
- 禁止硬编码 IP 地址、数据库连接串、密码、API Key
- 禁止 SELECT *，所有查询必须明确列出字段
- 所有 SQL 必须参数化，严禁字符串拼接（防注入）
- 禁止向外部 API 发送未脱敏数据（设备序列号、员工工号等敏感信息）

生产环境保护：
- 禁止生成任何针对生产环境的直接写操作（UPDATE/DELETE）
- 数据库结构变更（DDL）须单独提交审批
- 批量写操作须分批执行（每批 ≤ 500 条）
```

**可选约束（按任务类型添加）**：
- 覆盖率要求：`单元测试覆盖率目标 ≥ 70%`
- 性能要求：`接口响应 P99 < 500ms`
- 事务要求：`涉及多表写操作须使用 @Transactional`

---

### §5 输出格式要求（Output Format）

**目的**：规范交付物结构，确保每次输出都是完整的、可审查的标准交付。

**标准四段式交付物**（每个开发任务均须包含，缺少任意一项视为不完整交付）：

```
[输出格式要求]
请按以下四段式结构输出，缺少任何一段视为不完整交付：

① 实现思路分析（≤200字）
   说明技术方案选择理由和关键设计决策，重点说明"为什么这样做"而非"做了什么"

② 完整代码
   - 所有新建/修改文件的完整代码（禁止省略）
   - 文件头部注释：文件用途、作者（AI）、日期、关联需求单编号
   - 所有方法须有中文 JavaDoc

③ 单元测试用例
   - 覆盖核心业务逻辑和边界条件
   - 测试覆盖率目标 ≥ 70%
   - 使用 JUnit 5 + Mockito，遵循 Given-When-Then 结构

④ 使用说明与变更记录
   - 接口参数说明（含示例请求/响应 JSON）
   - 本次变更的影响范围
   - 需要执行的配置变更或数据库脚本
```

## 三、Prompt 版本管理规则

### 3.1 文件头部必填字段

每个 Prompt 文件的第一个代码块前必须有以下 frontmatter：

```markdown
**文件编号**：AI-MES-PROMPT-{类别}-{序号}
**版本**：V{主}.{次} · {YYYY-MM-DD}
**关联任务**：{Sprint}-{Story} {TaskID}
**作者**：{作者}
**需求单**：{REQ_NO}
**变更历史**：
| 版本 | 日期 | 变更内容 | 审批人 |
|------|------|--------|------|
| V1.0 | {DATE} | 初始版本 | {TL} |
```

### 3.2 文件命名规则

| 目录 | 命名格式 | 示例 |
|------|--------|------|
| `prompts/backend/` | `{功能}-template.md` | `code-gen-template.md` |
| `prompts/sql/` | `{功能}-template.md` | `query-template.md` |
| `prompts/frontend/` | `{功能}-template.md` | `component-template.md` |
| `prompts/devops/` | `{功能}-template.md` | `inspection-template.md` |

### 3.3 变更审批流程

```
开发 PR → Gitleaks 硬编码扫描 → TL 审批 MR → 合并到 main
                                    ↓
                          CI 自动触发断言库基准测试
                                    ↓
                          Critical 100% 通过才可合并
```

> **注意**：Prompt 变更后，CI/CD 自动触发断言库全量基准测试。禁止在生产使用的 Prompt 上直接试验性修改，须在 `feature/prompt-xxx` 分支上验证后再提交 MR。
